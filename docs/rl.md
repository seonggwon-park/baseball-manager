# 강화학습 환경 (bm-gym, 2026-11-20)

게임과 시뮬레이션은 같은 엔진을 쓴다. 이 환경은 그 엔진 위에서 감독의 결정을 학습하고 탐색하는 도구다. Rust 크레이트 `bm-gym`이 환경 본체이고, Python 패키지 `python/bm_gym`이 그것을 Gymnasium 인터페이스로 내보낸다.

**여기서 배운 결과는 엔진에 대한 것이다.** 학습 알고리즘은 시뮬레이터의 허점을 파고든다(명세 게이밍, Krakovna et al. 2020). 엔진에서 이기는 작전이 실제 야구에서도 이긴다고 말하려면, 그 작전이 기대는 엔진의 부분이 실측과 맞는지 따로 확인해야 한다. 엔진의 전술 영역 검증은 [`tactics.md`](tactics.md)에 있다.

## 1. 에이전트가 하는 일

에이전트는 한 구단의 공격을 맡는다. 자기 타자에게 공이 하나 던져지기 전마다 두 가지를 고른다.

- 타격 접근 5가지: 강공(`hit`), 희생번트(`sac_bunt`), 기습번트(`bunt_for_hit`), 히트 앤드 런(`hit_and_run`), 기다리기(`take`)
- 도루 지시 3가지: 주자 판단(`auto`), 금지(`hold`), 이번 투구에 출발(`steal`)

행동은 둘의 조합 15가지다(`approach × 3 + steal`). 나머지는 엔진의 AI 감독(`mlb` 성향, `tactics.md` 3절)이 한다. 상대 구단의 모든 결정과, 에이전트 구단의 투수 교체·대타·대주자·수비 위치·고의사구가 여기에 들어간다. 한 경기가 한 에피소드이고, 경기당 결정은 평균 149번이다(자기 공격의 투구 수).

- **공격만 맡기는 이유:** 엔진의 위임 플래그(`Auto`)가 수비 위치와 고의사구를 한 묶음(`defense`)으로 다룬다. 에이전트에게 고의사구만 주려면 이 묶음을 나눠야 한다. 엔진 수정이 필요해서 다음 단계로 미뤘다.
- **번트 방향:** AI 감독처럼 70%를 3루 쪽으로 댄다.
- **경기:** 메이저리그 구장 30곳(2025 MLB 규칙)과 능력치로 만든 구단 30개다(`bm validate --world`와 같은 선수 생성). 경기마다 두 구단과 맡을 쪽(원정·홈)을 무작위로 뽑는다. 구단은 `league_seed`로 정해지며, CLI의 같은 `--seed`와 같은 구단이다.

### 행동 마스크

상황에 맞지 않는 행동은 마스크로 알려 준다(`action_mask()`, Gymnasium 래퍼의 `info["action_mask"]`와 `action_masks()`; sb3-contrib MaskablePPO의 관례).

- 도루 지시(금지·출발): 보낼 주자가 있을 때만. 1루 주자와 빈 2루, 또는 2루 주자와 빈 3루.
- 희생번트: 1루나 2루에 주자가 있고 2아웃 미만일 때만.
- 히트 앤드 런: 보낼 주자가 있을 때만. 주자를 스스로 보내므로 도루 지시는 '주자 판단'과만 짝짓는다.

마스크 밖의 행동은 거부하지 않고 가장 가까운 행동으로 바꿔 실행한다. 먼저 도루 지시를 '주자 판단'으로 바꾸고, 그래도 안 되면 강공으로 바꾼다.

## 2. 관찰 (35개)

| 묶음 | 항목 | 척도 |
|---|---|---|
| 경기 | 이닝, 말 공격 여부, 홈 여부, 아웃(원핫 3), 주자(1·2·3루), 볼, 스트라이크, 점수차, 승리 기대값, 투구 수 | 이닝 (회−1)/8(최대 1.5), 점수차/5(±2에서 자름), 투구 수/100 |
| 타자 | 공격 가치(`quality`), 주력, 도루 능력, 번트 능력, 좌타석 여부(스위치 타자는 투수 반대편), 구종 인지, 배럴 정밀도, 배트 속도 | 평균 0, 퍼짐 약 1이 되게 맞춤 |
| 대기 타자 | 공격 가치 | 같음 |
| 주자 | 1·2·3루 주자의 주력과 도루 능력(비었으면 0) | 같음 |
| 투수 | 직구 구속, 투구 동작 시간(퀵모션), 좌투 여부, 피로(투구 수/체력), 디셉션 | 같음 |
| 포수 | 2루 송구 시간 | 같음 |

척도는 실제 경기 60개(8,940결정)에서 확인했다. 선수 특징은 평균 −0.26–+0.28, 표준편차 0.3–1.1이다. 이름과 순서는 `bm_gym.OBSERVATION_NAMES`에 있다.

## 3. 보상: 승리 기대값의 변화

기본 보상은 한 단계 동안 에이전트 구단의 승리 기대값이 바뀐 양이다. 마지막 단계에서 승리 기대값은 이기면 1, 지면 0이 된다. 그래서 한 경기의 보상 합은 '결과 − 첫 결정 때의 승리 기대값'이다. 이것은 승리 기대값을 잠재 함수로 쓴 보상 성형이고, 표가 틀려도 최적 정책은 바뀌지 않는다(Ng, Harada & Russell 1999). 좋은 표는 학습만 빠르게 한다. `reward="win"`을 주면 이긴 경기의 끝에만 1을 준다.

### 승리 기대값 표 (`bm we`)

`data/engine/win_expectancy.json`은 AI 감독끼리 치른 30만 경기(타석 2,267만 개, 4스레드로 599초)에서 센 표다. 칸은 이닝(1–9, 연장은 하나로) × 초·말 × 아웃 × 주자 상태 × 홈팀 점수차(±10에서 자름), 모두 10,080칸이다. 각 칸에 그 상태에서 시작한 타석 수와 그 가운데 홈팀이 이긴 수를 둔다. 표본이 적은 칸은 같은 이닝·초말·점수차를 아웃·주자 상관없이 묶은 값으로 당긴다. 그 묶음은 다시 초말·점수차만으로 묶은 값으로 당긴다(각 가중 타석 20개).

| 상황 (타석 시작) | 홈팀 승리 기대값 |
|---|---|
| 경기 시작 | 0.502 |
| 9회초, 홈 1점 앞섬, 주자 없음, 무사 | 0.848 |
| 9회말, 동점, 주자 없음, 무사 | 0.633 |
| 9회말, 동점, 1루, 무사 | 0.694 |
| 9회말, 동점, 2루, 1사 | 0.687 |
| 9회말, 1점 뒤짐, 만루, 2사 | 0.276 |
| 5회초, 홈 3점 앞섬, 주자 없음, 무사 | 0.858 |

- 엔진에는 말 공격의 이점 말고는 홈 이점이 없다. 그래서 경기 시작 때 홈팀 승리 기대값이 0.502다. 실제 MLB에서는 홈팀이 이보다 더 많이 이긴다.
- 이 표는 엔진의 AI 감독끼리의 표다. 에이전트가 다르게 지휘하면 실제 승리 확률은 표와 달라진다. 보상 성형에는 문제가 없다(위).
- 엔진을 바꾸면 표가 낡는다. `cargo run --release --bin bm -- we --games 300000`으로 다시 만든다.

## 4. 같은 순간을 여러 갈래로

환경은 진행 중인 경기째로 복제된다(Rust `ManagerEnv::clone`, Python `copy()`). 그래서 한 결정 시점에서 행동마다 같은 상태로 갈라 끝까지 시뮬레이션해, 행동의 값을 직접 잴 수 있다. `finish_with_ai()`는 남은 경기를 AI 감독에게 맡겨 끝까지 치르고 승패를 돌려준다.

## 5. 쓰는 법

```sh
# Rust: 환경 테스트와 승리 기대값 표
cargo test -p bm-gym
cargo run --release --bin bm -- we --games 300000

# Python (Rust 툴체인 필요; maturin이 crates/bm-py를 빌드한다)
pip install "./python[gym]"        # 개발 중이면: cd python && maturin develop --release
pytest python/tests
```

```python
import bm_gym
env = bm_gym.make(seed=1)                 # gymnasium.Env (또는 gymnasium.make("BaseballManager-v0"))
obs, info = env.reset(seed=7)
while True:
    mask = info["action_mask"]
    action = 0                            # 0 = 강공 + 주자 판단
    obs, reward, terminated, truncated, info = env.step(action)
    if terminated:
        break
print(info["won"], info["score"])
```

- **속도:** 이 컨테이너의 한 스레드에서 Python 바인딩은 초당 약 18,500결정(경기 125개)이고, Gymnasium 래퍼는 17,100결정이다. 엔진만 돌리면 경기당 8ms다(`bm validate`).
- **결정론:** 같은 `reset(seed)`와 같은 행동은 같은 경기를 만든다.

## 6. 한계

- 상대 AI 감독은 고정되어 있고 적응하지 않는다. 에이전트가 찾은 작전은 그 상대에 대한 답이다. 적응하는 상대와 셀프 플레이는 볼 배합 강화학습(5단계)에서 다룬다.
- 엔진의 전술 영역에는 알려진 차이가 있다(`tactics.md`). 1루 무사의 득점 기대값이 실측보다 낮고(0.803, 실측 0.859), 2·3루 1사 고의사구의 값은 부호가 틀렸다. 시프트 제한 효과는 실측의 3분의 1이다. 견제와 투구 시계도 없다. 이런 곳에 기대는 작전은 엔진의 버릇일 수 있다.
- 홈 이점이 없다(3절).
