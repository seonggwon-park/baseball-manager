# 강화학습 환경 (bm-gym, 2026-11-20)

게임과 시뮬레이션은 같은 엔진을 쓴다. 이 환경은 그 엔진 위에서 감독의 결정을 학습하고 탐색하는 도구다. Rust 크레이트 `bm-gym`이 환경 본체이고, Python 패키지 `python/bm_gym`이 그것을 Gymnasium 인터페이스로 내보낸다.

**여기서 배운 결과는 엔진에 대한 것이다.** 학습 알고리즘은 시뮬레이터의 허점을 파고든다(명세 게이밍, Krakovna et al. 2020). 엔진에서 이기는 작전이 실제 야구에서도 이긴다고 말하려면, 그 작전이 기대는 엔진의 부분이 실측과 맞는지 따로 확인해야 한다. 엔진의 전술 영역 검증은 [`tactics.md`](tactics.md)에 있다.

## 1. 에이전트가 하는 일

에이전트는 한 구단의 공격을 맡는다. 자기 타자에게 공이 하나 던져지기 전마다 두 가지를 고른다.

- 타격 접근 5가지: 강공(`hit`), 희생번트(`sac_bunt`), 기습번트(`bunt_for_hit`), 히트 앤드 런(`hit_and_run`), 기다리기(`take`)
- 도루 지시 3가지: 주자 판단(`auto`), 금지(`hold`), 이번 투구에 출발(`steal`)

행동은 둘의 조합 15가지다(`approach × 3 + steal`). 나머지는 엔진의 AI 감독(`mlb` 성향, `tactics.md` 3절)이 한다. 상대 구단의 모든 결정과, 에이전트 구단의 투수 교체·대타·대주자·수비 위치·고의사구가 여기에 들어간다. 한 경기가 한 에피소드이고, 경기당 결정은 평균 149번이다(자기 공격의 투구 수).

- **공격만 맡기는 이유:** 엔진의 위임 플래그(`Auto`)가 수비 위치와 고의사구를 한 묶음(`defense`)으로 다룬다. 에이전트에게 고의사구만 주려면 이 묶음을 나눠야 한다. 엔진 수정이 필요해서 다음 단계로 미뤘다.
- **번트 방향:** AI 감독처럼 70%를 3루 쪽으로 댄다.
- **경기:** 메이저리그 구장 30곳(2025 MLB 규칙)과 능력치로 만든 구단 30개다(`bm validate --world`와 같은 선수 생성). 경기마다 두 구단과 맡을 쪽(원정·홈)을 무작위로 뽑는다. 구단은 `league_seed`로 정해지며, CLI의 같은 `--seed`와 같은 구단이다.

### 행동 마스크

상황에 맞지 않는 행동은 마스크로 알려 준다(`action_mask()`, Gymnasium 래퍼의 `info["action_mask"]`와 `action_masks()`; sb3-contrib MaskablePPO의 관례).

- 도루 지시(금지·출발): 보낼 주자가 있을 때만. 1루 주자와 빈 2루, 또는 2루 주자와 빈 3루.
- 희생번트: 1루나 2루에 주자가 있고 2아웃 미만일 때만.
- 히트 앤드 런: 보낼 주자가 있을 때만. 주자를 스스로 보내므로 도루 지시는 '주자 판단'과만 짝짓는다.

마스크 밖의 행동은 거부하지 않고 가장 가까운 행동으로 바꿔 실행한다. 먼저 도루 지시를 '주자 판단'으로 바꾸고, 그래도 안 되면 강공으로 바꾼다.

## 3. 보상: 승리 기대값의 변화

기본 보상은 한 단계 동안 에이전트 구단의 승리 기대값이 바뀐 양이다. 마지막 단계에서 승리 기대값은 이기면 1, 지면 0이 된다. 그래서 한 경기의 보상 합은 '결과 − 첫 결정 때의 승리 기대값'이다. 이것은 승리 기대값을 잠재 함수로 쓴 보상 성형이고, 표가 틀려도 최적 정책은 바뀌지 않는다(Ng, Harada & Russell 1999). 좋은 표는 학습만 빠르게 한다. `reward="win"`을 주면 이긴 경기의 끝에만 1을 준다.

### 승리 기대값 표 (`bm we`)

`data/engine/win_expectancy.json`은 AI 감독끼리 치른 30만 경기(타석 2,280만 개, 4스레드로 약 600초; 2026-11-20 배트 위 접촉 위치 보정 뒤 다시 만듦)에서 센 표다. 칸은 이닝(1–9, 연장은 하나로) × 초·말 × 아웃 × 주자 상태 × 홈팀 점수차(±10에서 자름), 모두 10,080칸이다. 각 칸에 그 상태에서 시작한 타석 수와 그 가운데 홈팀이 이긴 수를 둔다. 표본이 적은 칸은 같은 이닝·초말·점수차를 아웃·주자 상관없이 묶은 값으로 당긴다. 그 묶음은 다시 초말·점수차만으로 묶은 값으로 당긴다(각 가중 타석 20개).

| 상황 (타석 시작) | 홈팀 승리 기대값 |
|---|---|
| 경기 시작 | 0.500 |
| 9회초, 홈 1점 앞섬, 주자 없음, 무사 | 0.843 |
| 9회말, 동점, 주자 없음, 무사 | 0.636 |
| 9회말, 동점, 1루, 무사 | 0.696 |
| 9회말, 동점, 2루, 1사 | 0.707 |
| 9회말, 1점 뒤짐, 만루, 2사 | 0.290 |
| 5회초, 홈 3점 앞섬, 주자 없음, 무사 | 0.844 |

- 엔진에는 말 공격의 이점 말고는 홈 이점이 없다. 그래서 경기 시작 때 홈팀 승리 기대값이 0.500이다. 실제 MLB에서는 홈팀이 이보다 더 많이 이긴다.
- 이 표는 엔진의 AI 감독끼리의 표다. 에이전트가 다르게 지휘하면 실제 승리 확률은 표와 달라진다. 보상 성형에는 문제가 없다(위).
- 엔진을 바꾸면 표가 낡는다. `cargo run --release --bin bm -- we --games 300000`으로 다시 만든다.

## 4. 같은 순간을 여러 갈래로

환경은 진행 중인 경기째로 복제된다(Rust `ManagerEnv::clone`, Python `copy()`). 그래서 한 결정 시점에서 행동마다 같은 상태로 갈라 끝까지 시뮬레이션해, 행동의 값을 직접 잴 수 있다. `finish_with_ai()`는 남은 경기를 AI 감독에게 맡겨 끝까지 치르고 승패를 돌려준다. Rust의 `ManagerEnv::rollout`은 지금 타석을 주어진 지시로 치른 뒤 나머지를 AI 감독에게 맡기고, 승패와 그 이닝 남은 득점을 돌려준다. `bm rollout`(6절)이 이것을 쓴다.

## 5. 쓰는 법

```sh
# Rust: 환경 테스트와 승리 기대값 표
cargo test -p bm-gym
cargo run --release --bin bm -- we --games 300000

# Python (Rust 툴체인 필요; maturin이 crates/bm-py를 빌드한다)
pip install "./python[gym]"        # 개발 중이면: cd python && maturin develop --release
pytest python/tests
```

```python
import bm_gym
env = bm_gym.make(seed=1)                 # gymnasium.Env (또는 gymnasium.make("BaseballManager-v0"))
obs, info = env.reset(seed=7)
while True:
    mask = info["action_mask"]
    action = 0                            # 0 = 강공 + 주자 판단
    obs, reward, terminated, truncated, info = env.step(action)
    if terminated:
        break
print(info["won"], info["score"])
```

- **속도:** 이 컨테이너의 한 스레드에서 Python 바인딩은 초당 약 18,500결정(경기 125개)이고, Gymnasium 래퍼는 17,100결정이다. 엔진만 돌리면 경기당 8ms다(`bm validate`).
- **결정론:** 같은 `reset(seed)`와 같은 행동은 같은 경기를 만든다.

## 6. 작전 롤아웃: 엔진 안에서 작전 하나의 값

`bm rollout`은 경기에서 실제로 나온 타석 시작 순간을 상황별로 모은다(2026-11-20 위치별 타구 질·구종 × 존 수정 뒤 엔진으로 다시 돌림). 그리고 그 순간을 복제해 작전마다 끝까지 시뮬레이션한다. 작전은 그 타석에만 쓰고, 다음 타석부터는 AI 감독이 지휘한다. 작전마다 같은 난수를 준다(공통 난수). 이것은 AI 감독을 기준 정책으로 한 롤아웃 정책 개선의 한 단계다(Tesauro & Galperin 1997). 상황마다 타석 300개, 작전마다 롤아웃 200번(4스레드로 1,152초)이다. 타석은 에이전트 구단이 늘 강공하고 주자는 스스로 판단하는 경기에서 뽑았다(공격 타석의 25%를 무작위로).

작전(그 타석에서):

- 희생번트: 2스트라이크 전까지 번트, 그 뒤 강공
- 기습번트: 첫 투구만 번트
- 도루: 첫 투구에 선두 주자를 보냄(주자의 판단과 상관없이)
- 히트 앤드 런: 첫 투구에
- 주자 묶기: 타석 내내 도루 금지

강공 대비 차이다. 타석별로 (작전 − 강공)을 구한 뒤 타석 평균을 냈고, ±는 타석 간 표준오차다. '득점'은 그 이닝이 끝날 때까지의 득점이다.

| 상황 (타석 시작) | 강공: 승리 / 득점 | 희생번트 | 도루 | 히트 앤드 런 | 주자 묶기 |
|---|---|---|---|---|---|
| 1루, 무사, 1–6회, 점수차 1 이하 | 0.568 / 0.834 | −1.04%p ± 0.29 / −0.075 | −2.84%p ± 0.30 / −0.256 | −1.15%p ± 0.28 / −0.082 | −0.53%p ± 0.27 / −0.005 |
| 1루, 무사, 7회 이후, 점수차 1 이하 | 0.587 / 0.819 | −0.77%p ± 0.26 / −0.064 | −2.80%p ± 0.32 / −0.208 | −0.94%p ± 0.24 / −0.079 | −0.25%p ± 0.26 / −0.005 |
| 2루, 무사, 7회 이후, 점수차 1 이하 | 0.589 / 0.990 | −1.64%p ± 0.29 / −0.085 | 3루 도루 −9.84%p ± 0.45 / −0.375 | | −0.17%p ± 0.27 / −0.003 |
| 1·2루, 무사, 7회 이후, 점수차 1 이하 | 0.637 / 1.324 | −0.32%p ± 0.26 / −0.033 | | | |
| 1루, 1사, 7회 이후, 점수차 1 이하 | 0.522 / 0.494 | −1.87%p ± 0.28 / −0.089 | −2.61%p ± 0.30 / −0.153 | −0.90%p ± 0.24 / −0.051 | |
| 1루, 2사, 모든 이닝 | 0.463 / 0.232 | | −1.22%p ± 0.22 / −0.113 | | −0.29%p ± 0.22 / +0.001 |

주자 없음·무사의 기습번트는 승리 +0.05%p ± 0.24, 득점 +0.004이다. 득점 칸의 표준오차는 0.004–0.012점이다.

- **강공보다 나은 작전은 없었다.** 가장 나은 것이 본전이다. 기습번트(+0.05%p ± 0.24), 1·2루 무사의 희생번트(−0.32%p ± 0.26)가 그렇다. 수정 전 엔진에서 본전이던 2사 1루 가장 빠른 주자 1/3의 도루는 이제 −0.99%p ± 0.37이다.
- **희생번트는 1루나 2루 주자만 있을 때 0.8–1.9%p를 잃는다.** 타자의 공격 가치를 셋으로 나눠도 어느 쪽도 이득이 아니다. 1루 무사·후반의 약한 타자 1/3도 −0.98%p ± 0.45다. 대상은 지명타자 규칙 아래의 야수들이다(투수 타석 없음).
  - 엔진은 1루 무사 번트 성공의 손실을 실제보다 작게 본다(득점 기대값 −0.161, Tango 2010–2015 표 −0.195; `tactics.md` 2절). 그러니 실제라면 이 번트는 더 손해일 것이다.
  - 1·2루 무사 번트가 본전에 가까운 것은 표와 맞는다. 성공한 번트의 득점 기대값 변화가 −0.061(Tango)로 작고, 한 점이라도 날 확률은 +0.066이다(엔진 +0.052, 실제보다 조금 작음).
- **도루를 무조건 시키면 손해다. 주자 스스로의 판단은 조금 이득이다.** 득점 변화를 엔진의 득점 기대값 표로 거꾸로 풀면, 1루 무사에서 첫 투구 도루의 성공률은 약 38%다. 가장 빠른 주자 1/3은 약 63%다. 둘 다 손익분기(69.7–69.8%, `tactics.md` 2절)보다 낮다. 엔진의 주자는 시간 여유가 있을 때만 스스로 뛰고, 그렇게 뛴 도루의 성공률은 76.8%다. 그래서 도루를 막으면(주자 묶기) 0.2–0.5%p를 잃는다.
  - 주자 주력별로 1루 무사·초반 도루: 느린 1/3 −4.4%p, 가운데 −3.5%p, 빠른 1/3 −0.7%p ± 0.5.
  - 3루 도루(2루 무사)는 주력과 상관없이 −7–−12%p다. 무사 3루 도루의 손익분기가 77.3%로 높기 때문이다.
- **AI 감독의 번트는 얼마나 손해인가.** AI 감독은 2025 MLB 빈도에 맞춰, 1–8회 주자가 있는 상황에서 경기당 0.37번(양 팀 합계) 번트를 시도한다(`tactics.md` 3절). 상황별 시도 횟수에 위 표의 손실을 곱하면 팀 경기당 약 0.21%p, 162경기에 약 0.33승이다. 작다.
- **이것이 말하지 않는 것:** 한 가지 작전을 그 타석에만 바꾼 값이다. 상대가 번트 수비를 바꾸거나, 볼카운트에 따라 작전을 바꾸는 효과는 들어 있지 않다. 엔진의 번트·도루 모델(성공 분포, 리드와 출발)은 리그 빈도와 결과에 맞췄을 뿐, 상황별 성공률을 따로 검증하지는 않았다.

## 7. 강화학습 시연: 표 형태 학습기 셋

`python/examples/q_learning.py`는 Python 환경 위에서 표 형태 학습기를 돌린다. 상태는 일부러 거칠게 잡았다. 아웃 × 주자 × 볼카운트 × '후반 접전'(7회 이후, 점수차 1 이하) 여부 × 타자(관찰의 `batter_quality`로 약·보통·강)이고, 모두 1,728칸이다. 보상은 승리 기대값의 변화다. 학습에 4만 경기(약 530만–680만 결정, 4프로세스로 361–439초; 2026-11-20 위치별 타구 질·구종 × 존 수정 뒤 엔진)를 쓰고, 같은 시드 2만 경기로 비교했다. 시드가 같으면 구단·구장·맡는 쪽이 같다. ±는 경기별 짝 차이의 표준오차다.

| 정책 | 승률 | 항상 강공 대비 |
|---|---|---|
| 항상 강공(`hit`) | 0.5024 | |
| AI 감독(`ai`, 공격 작전도 AI) | 0.5089 | +0.65%p ± 0.49 |
| Q-학습(한 표, 고정 학습률 0.05) | 0.3867 | −11.57%p ± 0.49 |
| 이중 Q-학습(학습률 1/n) | 0.2612 | −24.12%p ± 0.47 |
| 몬테카를로 + 신중한 정책 | 0.4936 | −0.88%p ± 0.40 |

- **AI 감독의 공격 작전은 항상 강공과 구별되지 않는다.** 차이 +0.65%p ± 0.49는 잡음 안이다. 6절의 롤아웃 어림(경기당 −0.21%p, 시즌 약 0.33승 손해)과 방향은 반대지만, 둘의 차이는 이 비교의 표준오차 2배 안이다.
- **Q-학습은 거의 모든 볼카운트에서 '기다리기'를 배웠다.** 잡음 섞인 추정값 15개의 최댓값을 다음 상태의 값으로 쓰면 값이 위로 쏠린다(최대화 편향, Sutton & Barto 2018 6.7절). 타석을 길게 끄는 행동일수록 그 쏠림이 여러 번 쌓여 좋아 보인다.
- **이중 Q-학습(Hasselt 2010)은 최대화 편향을 줄이지만 다른 함정에 빠졌다.** 학습률 1/n은 모든 목표값을 같은 무게로 평균한다. 그래서 다음 상태의 값을 아직 0으로 알던 초기의 목표값이 끝까지 남는다. 이 문제에서 정상 행동의 값은 음수로 내려가므로(탐험 중의 손해가 섞인다), 덜 시도한 작전일수록 0에 가까운 낙관적인 값을 유지한다. 탐욕 정책은 그런 작전(기다리기, 기습번트, 히트 앤드 런)을 고른다. 1,190칸이 강공을 떠났고, 그 값은 대부분 정확히 0이다.
- **몬테카를로 제어**는 행동 뒤에 실제로 따라온 반환값의 평균으로 값을 매긴다. 부트스트랩을 하지 않으므로 위의 두 편향이 없다. 다른 작전이 강공보다 2 표준오차 넘게 나을 때만 강공을 떠나게 했다(탐험률 0.15). 1,728칸 가운데 강공을 떠난 칸은 넷이었다. 1사 1루의 히트 앤드 런 두 칸(0-1, 1-0, 보통 타자), 1사 1루 0-0 강한 타자의 주자 묶기, 2사 주자 없음 3-2 강한 타자의 기습번트로, 학습 중 추정은 +2.1 – +6.8%p였다. 그런데 평가에서 이 정책은 강공보다 0.88%p ± 0.40 나빴다. 칸 1,728개마다 대안 여러 개를 2 표준오차로 견주면 우연히 그 선을 넘는 칸이 나온다(다중 비교). 그 넷이 거짓 발견이었다. 결국 세 학습기 모두 강공보다 나은 정책을 찾지 못했다. 6절의 롤아웃 결론(강공보다 나은 작전이 없음)과 같다.
- **교훈:** 이 문제에서 행동 간 차이는 승리 확률 0.5–5%p다. 한 경기 결과의 잡음(표준편차 0.5)에 비해 아주 작다. 그래서 학습기의 작은 편향이 결과를 뒤집는다. 같은 상태를 복제해 공통 난수로 비교하는 6절의 롤아웃이 이 질문에는 더 믿을 만한 도구다. 강화학습으로 더 나아가려면 볼카운트를 넣은 잠재 함수, 함수 근사, 훨씬 많은 표본이 필요하다.

## 8. 한계

- 상대 AI 감독은 고정되어 있고 적응하지 않는다. 에이전트가 찾은 작전은 그 상대에 대한 답이다. 적응하는 상대와 셀프 플레이는 볼 배합 강화학습(README의 '다음 단계')에서 다룬다.
- 엔진의 전술 영역에는 알려진 차이가 있다(`tactics.md`). 1루 무사의 득점 기대값이 실측보다 낮고(0.829, 실측 0.859), 2·3루 1사 고의사구의 값은 부호가 틀렸다. 시프트 제한 효과는 실측의 3분의 1 남짓이다. 견제와 투구 시계도 없다. 이런 곳에 기대는 작전은 엔진의 버릇일 수 있다.
- 홈 이점이 없다(3절).

## 9. 볼 배합: 투수의 공을 부르는 환경 (2026-11-20)

사용자 결정(2026-11-20): 타자는 투수의 평소 비율과 **다른 만큼만** 적응한다. 행동은 **구종 × 공략 의도**이다. 보상은 **투구별 득점 가치**이다.

### 9.1 타자가 투수를 읽는 방식 (`pitching::Tendency`)

지금까지 엔진의 타자는 늘 빠른 공에 타이밍을 맞추고, 투수의 카운트별 평소 구종 비율만 알았다. 그래서 투수가 비율을 크게 바꿔도 따라오지 못했다. 학습하는 투수는 이 빈틈을 파고들 것이다. 실제 타자의 기대는 최근에 본 공을 따른다(Gray 2002). 그래서 같은 경기에서 지금 투수가 던진 공을 타선 전체가 함께 기억하게 했다.

- **기억하는 것:** 구종마다 '던졌으면 1 − 평소 비율, 안 던졌으면 − 평소 비율'의 지수 가중 평균이다(반감기 25구). 평소 비율은 그 카운트, 그 타석 방향에서의 선택 가중치다. 투수가 평소대로 던질 때 이 평균이 우연히 흔들리는 폭(분산)도 함께 기억한다.
- **반영하는 것:** 우연 폭의 2배를 넘는 편차만 반영한다. 위치 예상(사전 위치)은 옮겨진 비율을 따른다. 타이밍은 평소보다 늘어난 변화구 몫만큼 빠른 공에서 평균 공 쪽으로 기운다.
- **세기:** `ModelParams::tendency_strength`로 정한다. 엔진의 기본값은 0이라 게임과 모든 기존 명령의 출력이 바이트 단위로 같다(`bm validate`, `bm game`으로 확인). 투수 환경에서는 1이다.
- **측정:**
  - 평소 비율대로 던지면 타자의 타이밍이 평균 0.04 ms 움직인다. 우연 폭을 넘는 편차가 있는 투구는 15%다.
  - 변화구 하나만 40구 던지면 타자는 그 공을 22 ms 늦게 예상한다(0.399 → 0.421 s).
  - AI의 평소 볼 배합으로 같은 시드 4,000경기를 치렀다. 경기당 실점은 읽기를 끄면 4.397, 켜면 4.354이다(9.4절; 차이는 잡음 안).
- **위치도 같은 방식으로 읽는다(사용자 결정 2026-11-20):** 공이 존에 들어왔으면 '1 − 평소 존 비율', 아니면 '− 평소 존 비율'의 지수 가중 평균과 그 우연 폭을 기억한다. 평소 존 비율은 카운트별 MLB 2025 Statcast 값이다(`zone_usual`). 엔진의 AI 호출은 이 값과 1.4%p 안에서 같다. 우연 폭 2배를 넘는 만큼에 `zone_lean`(0.18)을 곱한 비율만큼 스윙 준비(`swing_base`)가 늘거나 준다(±50%에서 자름). 투수가 존에 더 자주 넣는다고 읽으면 타자가 더 자주 치러 나온다.
  - **근거(약함):** 2025 선발(120이닝 이상)에서 투수의 존 비율이 1%p 높으면 타자의 존 안 스윙률이 0.35%p 오른다(표준오차 0.11). 이 항이 없는 엔진은 0.23%p(0.06)이다. 남은 0.12%p를 '알고 있는 존 비율에 대한 타자의 반응'으로 보고 크기를 정했다. 그러나 이 차이는 표준오차 하나 안이라 0과 구별되지 않는다. 존 밖 스윙률은 실측(−0.09%p)에서도 엔진(−0.06%p)에서도 투수의 존 비율을 따르지 않는다. 그런데 이 항은 스윙 준비에 곱하므로 존 밖 스윙도 비례해서 움직인다. 우연을 넘어 10%p를 읽으면 존 안 스윙이 1.2%p, 존 밖 스윙이 0.5%p 는다.
  - **크기:** 우연 폭을 넘는 만큼만 읽으므로 작다. 경기 내내 평소보다 10%p 더 존에 넣는 투수도 평균 0.7%p만 읽힌다(스윙 준비 +0.1%). 20%p 더 넣으면 4%p가 읽힌다(+0.7%). AI의 평소 호출에서는 투구의 5.4%에서만 기울기가 생기고, 평균 크기는 0.02%다(300경기, 4만 4,114구).
- **한계:** 반감기 25구와 우연 폭 2배는 실측에 맞춘 값이 아니라 가정이다. 위치 읽기의 크기도 약한 근거에 기댄다.

### 9.2 볼카운트를 포함한 득점 기대값 (`bm re`)

`bm re`는 AI 감독끼리의 경기에서 투구 직전 상태(주자 8 × 아웃 3 × 볼 4 × 스트라이크 3)마다 그 반 이닝이 끝날 때까지의 득점을 센다. 1–8회와 9회초만 쓴다. 9회말 이후는 끝내기로 일찍 끝날 수 있고, 연장은 승부치기 주자가 있기 때문이다. 30만 경기에서 투구 8,312만 개다(`data/engine/run_expectancy.json`, 4스레드로 약 600초; 2026-11-20 배트 위 접촉 위치 보정 뒤 다시 만듦). 주자 없음·무사에서 0-0은 0.484점, 3-0은 0.703점, 0-2는 0.399점이다(배트 위 접촉 위치 보정 전 0.481, 0.703, 0.394점; 위치별 타구 질 수정 전 0.463, 0.672, 0.383점).

볼카운트의 값(0-0 대비, 주자·아웃 상태를 투구 수로 가중 평균)을 Walsh(2008)의 표와 비교했다:

| 카운트 | 0-1 | 0-2 | 1-0 | 1-1 | 1-2 | 2-0 | 2-1 | 2-2 | 3-0 | 3-1 | 3-2 |
|---|---|---|---|---|---|---|---|---|---|---|---|
| 엔진 | −0.040 | −0.099 | +0.030 | −0.018 | −0.082 | +0.084 | +0.025 | −0.049 | +0.187 | +0.119 | +0.034 |
| Walsh 2008 | −0.044 | −0.106 | +0.038 | −0.015 | −0.082 | +0.140 | +0.037 | −0.039 | +0.220 | +0.142 | +0.059 |

차이는 RMS 0.023점이다(배트 위 접촉 위치 보정 전 0.022점, 위치별 타구 질 수정 전 0.026점). 엔진을 Walsh 값에 회귀하면 기울기가 0.82로, 볼카운트의 효과가 약 5분의 1 작다. 타자에게 유리한 카운트(2-0, 3-1, 3-2)에서 특히 작다. Walsh의 자료는 득점이 더 많던 시기의 것이라 그 차이도 섞여 있다.

### 9.3 환경 (`bm_gym::PitchingEnv`, Python `bm_gym.PitchingEnv`·`BaseballPitching-v0`)

- **행동:** 24가지다(구종 8 × 의도 3). 지금 투수가 던지는 구종만 고를 수 있게 마스크로 알린다. 의도는 엔진의 카운트별 겨냥표(`zone_intent`)에서 가져온다.
  - 공략: 표의 최댓값 +0.90으로, 3-1과 같다.
  - 보통: 그 카운트의 값이다.
  - 유인: 표의 최솟값 −0.95로, 0-2와 같다.
  - 겨냥점·제구 오차·유인 방향은 엔진 그대로다. 같은 커터를 2,000구 던지면 존 밖 비율이 공략 42%, 보통(1-1) 48%, 유인 54%다.
- **진행:** 투구 교체·대타·고의사구·수비 위치·공격은 양 팀 모두 AI 감독이 맡는다. 투구 직전까지의 감독 교체는 `GameSim::settle`로 먼저 처리한다. 그래서 에이전트는 실제로 던질 투수를 보고 고른다.
- **관찰:** 71개다. 카운트, 아웃, 주자, 이닝, 점수 차, 득점 기대값, 타자(같은 손 여부, 수준, 선구안, 배럴, 배트 속도), 투수(손, 피로)를 담는다. 구종마다 보유 여부, 평소 비율, 타자에게 읽힌 편차, 제구, 직전 공을 담는다. 첫 공 여부, 타자의 타이밍 기울기, 위치 읽기로 바뀐 스윙 준비(`batters_zone_lean`)도 들어 있다.
- **보상:** −(득점 기대값의 변화 + 그 공으로 난 점수)이다. Statcast의 투구별 득점 가치와 같은 정의다. 반 이닝 동안의 합은 '시작 때 득점 기대값 − 실점'이므로, 가장 좋은 정책은 실점이 가장 적은 정책이다(Ng 외 1999).
- **상수 흔들기(`perturb`):** 경기마다 타자의 지각 상수를 흔든다.
  - 변화구 알아채기: ±0.03(선구안 눈금)
  - 알아챈 구종 보내기: ±0.05
  - 사전 위치의 당김: ±15%
  - 타이밍 보정: ±5%
  - 오판·늦은 스윙 척도: ±10%
  - 정책이 상수 한 벌에 기대어 살지 못하게 하려는 것이다.

### 9.4 실험 (`python/examples/pitch_mix.py`)

- **가치표(`collect`):** 타자가 읽지 않는 상태에서 2만 경기 동안 공을 무작위로 불렀다(투구 302만 개). 볼카운트 × 타석 방향 × 구종 × 의도마다 투구의 득점 가치를 평균했다.
- **비교(`evaluate`):** 같은 시드 4,000경기(같은 구단·구장·편)를 아래 정책으로 치렀다. ±는 경기별 짝 차이의 표준오차다.
  - AI: 엔진의 선택(평소 비율, 보통 의도)
  - 탐욕: 표에서 가장 좋은 호출을 매번 한다
  - 구종 탐욕: 가장 좋은 구종을 보통 의도로 던진다
  - 학습: REINFORCE로 200회(1만 9천 경기) 학습한 정책이다. 타자가 읽고 상수를 흔든 환경에서 학습했고, 할인율 0.95, 카운트별 기준선을 썼다.

탐욕 정책의 이득은 엔진을 고칠 때마다 이렇게 움직였다(타자가 읽지 않음 / 읽음, 상수 흔들기 없음):

| 엔진 | 탐욕 | 구종 탐욕 |
|---|---|---|
| 위치별 타구 질 수정 전 (구종만 읽음) | −0.576 / −0.374 | −0.314 / −0.222 |
| 위치별 타구 질 수정 뒤 (구종만 읽음) | −0.804 / −0.480 | −0.492 / −0.485 |
| 구종 × 존 수정과 위치 읽기 뒤 | −0.695 / −0.484 | −0.580 / −0.578 |
| 배트 위 접촉 위치 보정 뒤 (지금) | −0.641 / −0.296 | −0.479 / −0.469 |

- **탐욕 정책:** 공의 81%를 '공략'으로 던지고 빠른 공은 32%다(AI 54%). 스위퍼 24%, 체인지업 21%, 슬라이더 13%, 스플리터 9%를 던진다(AI 9%, 8%, 14%, 3%). 타자가 읽지 않으면 경기당 0.64점(15%)을 덜 내준다. 162경기면 100점이 넘는 차이로, 볼 배합만으로 얻기에는 지나치게 크다. 타자가 읽으면 0.30점이 남는다.
- **타자의 읽기가 이 이득의 절반 남짓(0.35점)을 지운다.** 직전 엔진에서는 0.21점이었다. 두 값의 차이는 그 표준오차(짝 차이 표준오차로 어림하면 0.12점 이하) 안팎이라 엔진 변경의 효과인지 구별되지 않는다. 이번 실행은 구종 읽기와 위치 읽기를 따로 끄지 않았다. 직전 엔진들의 비교로는 위치 읽기가 거의 일하지 않았다(구종만 읽는 엔진 −0.480, 둘 다 읽는 엔진 −0.484; 엔진도 달랐다). '공략' 의도는 존 비율을 평소보다 몇 %p만 올리고(9.3절: 커터 2,000구에서 공략의 존 밖 비율 42%, 보통 48%), 타자는 우연 폭 2배(약 12%p)를 넘는 만큼만 읽기 때문이다(9.1절).
- **구종 탐욕:** 빠른 공을 67%로 더 많이 던지고 0.48점을 덜 내준다. 타자가 구종을 읽어도 이득이 그대로다(−0.47점). 평소보다 빠른 공을 10%p 더 던져도 우연 폭을 넘는 편차는 작기 때문이다. 실제 MLB 투수는 최소최대 전략보다 빠른 공을 너무 많이 던진다는 실증 연구(Kovash & Levitt 2009)와 반대 방향이다.
- **학습 정책:** 빠른 공을 57%(포심 31%, 싱커 21%), 공략을 12%로 바꿨다. 학습한 환경(읽음·흔들기)에서 −0.15점이고, 다른 설정에서 −0.15 – −0.22점이다. 수렴하지 않은 결과이므로 이것으로 결론을 내지 않는다.
- **AI의 평소 볼 배합은 읽기를 켜도 거의 같다**(4.393 대 4.390).

### 9.5 찾은 것: 엔진의 위치별 타구 질과 고친 뒤

첫 실험(위치별 타구 질 수정 전)에서 탐욕 정책의 이득이 어디서 오는지, 투구 위치를 Statcast식 네 구역으로 나눠 실측과 견줬다. 구역은 공 중심이 규정 존 가장자리에서 공 하나 폭(2.9 in) 안쪽이면 한가운데, ±2.9 in 안이면 경계, 바깥으로 2.9–8.7 in면 유인, 그 너머면 버림이다. 실측은 2025 Statcast 표본 12만 5,858구(`delta_run_exp`)이고, 엔진은 AI의 평소 호출로 3,000경기다. 값은 100구당 득점(타자 기준)이다. 표는 실측 / 수정 전 엔진(43만 3,381구) / 지금 엔진(43만 5,720구; 위치별 타구 질·구종 × 존·배트 위 접촉 위치 보정 뒤)이다.

| 구역 | 투구 비율 | 득점 가치 | 0–1스트라이크 인플레이 100개당 | 0–1스트라이크 헛스윙/스윙 |
|---|---|---|---|---|
| 한가운데 | 32.6% / 33.1% / 33.2% | −1.51 / −2.19 / −1.63 | +6.75 / +3.84 / +5.73 | 13.4% / 18.3% / 16.1% |
| 경계 | 34.4% / 34.1% / 34.1% | −1.62 / −1.02 / −1.45 | +0.01 / +3.71 / +1.11 | 26.7% / 25.6% / 27.5% |
| 유인 | 20.1% / 20.0% / 20.0% | +2.14 / +2.28 / +1.79 | −2.13 / +5.71 / −4.80 | 56.8% / 50.4% / 61.2% |
| 버림 | 13.0% / 12.8% / 12.8% | +4.41 / +4.70 / +5.02 | −3.52 / +13.31 / −14.36 | 90.9% / 79.5% / 87.4% |

- **수정 전:** 투구 위치 분포와 스윙률은 실측과 같았지만(0–1스트라이크 한가운데 스윙 64.2%, 실측 64.4%) **맞힌 공의 질이 위치에 따라 충분히 달라지지 않았다.** 엔진의 타자는 한가운데 공을 실측보다 약하게 치고 더 자주 헛쳤고, 경계와 바깥 공은 실측보다 잘 쳤다. 그래서 '한가운데로 던지기'가 실제보다 쌌다. 9.4절의 첫 수치는 야구에 대한 발견이 아니라 엔진의 빈틈을 잰 것이었다(사양 게이밍, Krakovna 외 2020).
- **고친 뒤**(`physics-model.md` 5.1절 '공 위치에 따른 타구 질', '구종 × 존 안팎', '배트 위 접촉 위치의 흩어짐'): 구역별 득점 가치가 실측 쪽으로 왔다(한가운데 −2.19 → −1.63, 경계 −1.02 → −1.45). 경계 공의 인플레이 타구도 실측에 가까워졌다(+1.11, 실측 +0.01; 배트 위 접촉 위치 보정 전 +2.40). 유인 공의 인플레이 타구는 반대로 실측보다 나쁘다(−4.80, −2.13). 존 밖 공을 아주 약하게 맞힌 타구가 너무 많기 때문이다(`physics-model.md` 같은 절의 남은 차이; 버림 칸은 인플레이 타구가 적어 흔들린다). 투 스트라이크 유인구의 헛스윙이 많다(55.0%, 실측 43.1%). 실측 타자는 투 스트라이크에서 유인구의 헛스윙을 크게 줄이는데(56.8% → 43.1%), 엔진은 61.2% → 55.0%만 줄인다. 존 아래 편향의 구종별 배수(`below_kind`)에 투 스트라이크 보호(`two_strike_reach`)가 걸리지 않기 때문으로 보인다(확인하지 않았다).
- **그래도 탐욕 정책의 이득은 남았다**(9.4절, −0.64점). 이제 그 이득은 '한가운데로'가 아니라 '변화구를 존 안으로'에서 온다. 탐욕 정책은 스위퍼·체인지업·스플리터를 평소의 2.4–2.8배 던지고 81%를 공략으로 던진다. 존 안 변화구는 엔진에서 아직 실측보다 투수에게 유리하다(100구당 슬라이더 −2.29, 실측 −1.48; 스위퍼 −2.64, −2.19; 체인지업 −2.15, −1.81; 스플리터 −1.95, −1.30). 배트 위 접촉 위치 보정 뒤 존 안 변화구의 타구 속도는 실측에 가까워졌으므로(슬라이더 90.2, 실측 90.4 mph), 남은 차이는 맞은 공의 발사각과 루킹 스트라이크에 있다. 슬라이더의 차이는 홈런 −0.53점, 루킹 스트라이크 −0.32점, 헛스윙 −0.07점으로 나뉘고, 존 안 슬라이더 타구는 땅볼이 많다(46.2%, 실측 40.5%; `physics-model.md` 5.1절 '구종 × 존 안팎'의 남은 차이). 볼 배합 학습의 결론을 야구로 옮기려면 이 칸들을 먼저 맞춰야 한다. 타자가 그런 투수에게 적응하는 폭도 작다. 실제 타자가 '존 안 변화구가 많다'에 얼마나 빨리, 얼마나 크게 반응하는지는 이 프로젝트에서 재지 못했다.
